# Product Requirements Document(PRD)

## 1. 프로젝트 개요 (Project Overview)

- **프로젝트 명**: AI DREAM TELLER (AI 꿈 해몽 서비스)
- **목표**: 사용자가 입력한 꿈 내용을 AI가 분석하여 심층적인 해몽과 조언을 제공하는 수익형 웹 서비스
- **핵심 가치 1**: 신비롭고 직관적인 UI 경험과 정확도 높은 AI 분석을 통해서 사용자에게 인사이트와 재미 제공.
- **핵심 가치 2**: 프로이트, 칼 융, 신경과학, 게슈탈트 등 해몽을 맡기고 싶은 전문 분야를 선택해서 해몽 요청 가능.

## 2. 타겟 유저(Target Audience)

- 꿈의 의미를 검색해보는 습관이 있는 20-40대 남녀.
- 모바일 환경에서 간편하게 결과를 확인하고 공유하고 싶어하는 유저.

## 3. 기술 스택(Tech Stack)

- **Web Framework**: Next.js 16.1.6(App Router)
- **Language**: TypeScript
- **Styling**: Tailwind CSS, Shadcn/ui
- **Backend & DB**: Next.js API Routes, Supabase
- **Auth & Session**: Supabase Auth (`@supabase/ssr`, `@supabase/supabase-js` 기반 쿠키 세션, Google·Kakao 공식 디자인 규격 소셜 로그인 및 개발/프로덕트 동적 도메인 자동 라우팅)
- **Payments**: Toss payments (최신 v2 `@tosspayments/tosspayments-sdk` 주문서형 결제위젯)
- **Data Mocking**: `@faker-js/faker` (`urlPicsumPhotos` 기반 고화질 꿈 시각화 연동)
- **AI**: Gemini with gemini sdk
- **Notification**: Telegram Bot API (운영자 실시간 알림 봇 - 결제 완료/실패 및 AI 해몽 SUCCESS/FAIL 모니터링)

## 4. 디자인 가이드(Design Guide)

- **Theme**: Mystical Archive & Pensieve (Bright Ivory Base & Ethereal Magical Aura)
  - 해리포터풍의 신비로운 마법 서재(Grand Archive) 및 기억/꿈의 실타래를 들여다보는 펜시브(Pensieve) 메타포 적용
  - 어둡고 무거운 고딕이 아닌, **'밝은 아이보리 양피지 캔버스'** 위에 별빛 오로라가 일렁이는 지적이고 신비로운 분위기
- **Colors**:
  - Base: Warm Ivory Canvas (`#FAF8F5`, `#FDFBF7`)
  - Accent / Gradients: Moonlight Lavender (`#E8E0F8`), Ethereal Aurora (Soft Pink `#FCE7F3`, Sky Blue `#E0F2FE`), Starlight Gold/Amber Point (`#D4AF37`)
  - Text: Deep Charcoal Violet (`#1E1B2E`) & Muted Plum (`#4B4562`)
- **Interactions & Atmosphere**:
  - 부드러운 스크롤 애니메이션 및 카드 호버 시 별빛/오로라 발광(Luminescent Glow) 효과
  - 마법 인장(Wax Seal) 모양의 디테일 뱃지 및 로딩 시 펜시브 안에서 은빛 실타래가 모여드는 몽환적인 파동 애니메이션
  - 직관적이고 세련된 현대적 UI 위에 클래식한 마법 서재 감성을 조화롭게 융합



## 5. 프론트엔드 요구사항 (Frontend Requirements)

### 5.1 전체 레이아웃 (Global Layout)

1. **상단 네비게이션 바 (Header)** 
   - (공통) 홈 로고, 꿈 피드(`/feeds`), 해몽 시작 CTA 버튼(`[해몽 시작 ✨]`)
   - (비회원 상태) 로그인(`/auth`), 비회원 주문 조회(`/guest-login`) 메뉴 노출 (마이페이지 및 로그아웃 은닉)
   - (회원 로그인 상태) 마이페이지(`/my-page`), 로그아웃 버튼 노출 (로그인 및 비회원 주문 조회 링크 은닉, 클릭 시 Supabase 세션 및 쿠키 무효화 후 홈으로 리다이렉트)
   - (인증 상태 관리) 전역 `AuthProvider` 컨텍스트 및 `useAuth()` 훅을 통해 Supabase Auth 및 로컬 세션 상태를 실시간 감지하여 데스크톱 GNB 및 모바일 Drawer에 동기화 반영
   - (반응형) 모바일 환경(md 미만)에서는 우측 상단 햄버거 메뉴 아이콘 제공. 클릭 시 위에서 아래로(Top) 내려오는 풀 너비(Full-width) Drawer를 통해 메뉴 노출 가능.

2. **Body**
   - 각 페이지 별 주요 내용 렌더링

3. **Footer**
   - 사업자 정보(상호명, 대표자, 사업자번호, 주소 등), 이용약관 링크, 개인정보처리 방침 링크, 문의하기 링크 포함
   - 모든 페이지 하단에 고정 노출되는 글로벌 레이아웃 구조 적용

4. **Head & Meta**
   - SEO, Open Graph, GA4 등 Analytics 설정

## 6. 백엔드 요구사항 및 API 구조 (Backend Requirements & API Structure)

프론트엔드와 독립적으로 기능할 수 있도록 RESTful하고 직관적인 API 구조로 Next.js Route Handlers(API Routes)를 설계합니다.

### 6.1 인증 및 권한 (Auth)

- `POST /api/auth/login`
  - 설명: 소셜 로그인(Google, Kakao) 인증을 위해 Supabase Auth 인스턴스를 통해 각 제공업체의 권한 승인 페이지로 리다이렉트합니다.
- `GET /auth/callback` (구현완료) [x]
  - 설명: 소셜 로그인 최종 승인 후 Supabase에서 반환된 인증 코드(`code`)를 세션으로 교환하고, 개발(localhost) 및 프로덕션(Vercel) 환경에 맞는 도메인을 자동 감지하여 지정된 목적지(`/dream-teller` 등)로 303 리다이렉트합니다.
- `POST /api/auth/logout`
  - 설명: 현재 활성화된 사용자의 세션을 종료하고 로그아웃 처리합니다.
- `POST /api/auth/guest` (구현완료) [x]
  - 설명: 전화번호와 비밀번호를 전달받아 유효성을 검증하고 비회원용 세션 토큰 및 쿠키를 발급합니다.
  - 반환값: 비회원 인증 토큰 및 게스트 유저 프로필 객체.

### 6.2 사용자 (Users)

- `GET /api/users/me`
  - 설명: 현재 로그인한 회원/비회원의 프로필 및 기본 정보를 반환합니다.
- `PATCH /api/users/me`
  - 설명: 사용자의 프로필 정보(예: 닉네임)를 수정합니다.

### 6.3 주문 및 결제 (Orders & Payments)

- `POST /api/orders`
  - **설명**: 꿈 입력 데이터, 선택 옵션, 전문 학파를 바탕으로 토스 결제창 호출 직전 결제 대기 주문서(`status='pending'`)를 DB에 사전 생성합니다.
  - **요청 Body**: `{ dreamContent, expertField, includesImage, totalAmount, guestInfo?: { phone, password } }`
  - **금액 무결성 검증 (Tampering 방어)**:
    - 기본 텍스트 해몽: 1,500원
    - AI 이미지 생성 옵션 포함: 2,000원
    - 클라이언트에서 전송한 `totalAmount`가 서버의 단가 정책과 1원이라도 불일치할 경우 400 Bad Request 에러 반환 및 주문 생성 즉시 차단.
  - **주문 식별자 규격**: 토스페이먼츠 v2 위젯 규격(6~64자 영문/숫자/-/_ 허용)을 준수하는 고유 `order_id` 발급 (예: `DREAM_${timestamp}_${randomHex}` 또는 표준 UUID).
  - **회원/비회원 분기 및 비밀번호 암호화**:
    - **회원**: 세션 쿠키에서 `user.id` 추출하여 `orders.user_id`에 바인딩.
    - **비회원**: `guestInfo`의 `phone`(숫자만 정제) 및 `password`를 수신하여, `users` 테이블에 게스트 계정을 upsert 생성하고 비밀번호는 단방향 솔트 해시(`guest_password_hash`)로 암호화하여 저장(평문 저장 절대 금지). 이후 발급된 guest의 `id`를 `orders.user_id`에 바인딩.
  - **응답**: `{ success: true, data: { orderId, totalAmount, orderName } }`

- `GET /api/orders`
  - **설명**: 현재 로그인한 활성 회원의 전체 구매 이력 리스트를 반환합니다. (마이페이지 `/my-page` 용도)
  - **보안/인가**: Supabase Auth 세션 검증 필수 (미인증 시 401 Unauthorized).
  - **응답 데이터**: `orders` 목록 최신순 정렬 및 각 주문에 매핑된 `dream_results.analysis_status` 포함.

- `GET /api/orders/[id]`
  - **설명**: 특정 주문의 상세 구매 정보와 생성 완료된 AI 꿈 해몽 결과를 1:1 조인하여 반환합니다.
  - **소유권 인가 검증 (IDOR 방어)**:
    - **회원**: 세션 `user.id`와 주문의 `orders.user_id`가 일치하는지 검증.
    - **비회원**: HttpOnly `dream_teller_guest_token` 쿠키를 복호화/대조하여 주문의 소유주와 일치하는지 검증.
    - 타인의 주문이거나 미인가 요청인 경우 403 Forbidden 또는 404 Not Found를 반환하여 타인의 꿈 본문 및 결과 열람을 원천 차단.
  - **응답 데이터**: 주문 정보(`orders`) + 해몽 결과(`dream_results`: 4대학파 분석, 상징, 심리 처방, 이미지 URL, `is_public`).

- `GET /api/orders/guest`
  - **설명**: 비회원 세션 쿠키를 인증하여 해당 비회원의 주문 내역 리스트를 반환합니다. (비회원 조회 `/guest-check` 용도)
  - **보안/인가**: HttpOnly `dream_teller_guest_token` 쿠키 검증 (미인증 시 401 Unauthorized).
  - **데이터 격리**: 인증된 게스트 유저의 `phone_number`로 체결된 주문만 필터링하여 타 비회원 주문과 완벽 격리 반환.

- `POST /api/payments/confirm` (구현완료) [x]
  - **설명**: 토스페이먼츠 결제 승인 API를 호출하여 최종 결제 완료 처리를 수행하고 후속 AI 파이프라인을 트리거합니다.
  - **요청 Body**: `{ paymentKey, orderId, amount }`
  - **1단계: 결제 무결성 사전 검증**:
    - DB `orders` 테이블에서 `orderId` 조회. 존재하지 않을 시 404 Not Found.
    - DB에 기록된 `total_amount`와 클라이언트가 승인 요청한 `amount`를 대조하여 1원이라도 불일치 시 토스 API 호출 차단 및 400 Bad Request.
  - **2단계: 동시성 제어 및 멱등성 보장 (Replay Attack 방어)**:
    - 이미 `payment_status = 'paid'`인 주문에 대해 중복 요청 시, 추가 토스 승인 호출 없이 기존 결제 성공 응답을 즉각 반환하여 이중 승인/과금 원천 차단.
  - **3단계: 토스페이먼츠 v1 승인 엔드포인트 호출**:
    - `https://api.tosspayments.com/v1/payments/confirm` 엔드포인트를 `TOSS_SECRET_KEY` 기반 Basic Auth로 호출.
  - **4단계: DB 원자적 상태 갱신**:
    - `orders.payment_status` = `'paid'`, `orders.payment_key` = `paymentKey`, `orders.approved_at` = 현재시각 업데이트.
    - `dream_results` 테이블에 초기 레코드(`order_id`, `analysis_status: 'processing'`) 생성.
  - **5단계: 후속 비동기 파이프라인 트리거 (Non-blocking)**:
    - **텔레그램 알림 발송**: 결제 완료 내역(상품명, 유저식별자, 결제금액, 꿈 내용 일부) 관리자 봇 전송.
    - **AI 해몽 생성 비동기 호출**: `POST /api/ai/generate`를 비동기 호출하여 즉각적인 분석 가동 (AI 실패 시에도 결제 승인 자체는 보존).

- `POST /api/payments/fail`
  - **설명**: 카드사 한도 초과, 잔액 부족, 사용자 결제 취소 등으로 결제 승인 실패 시 실패 사유를 DB에 기록합니다.
  - **요청 Body**: `{ orderId, code, message }`
  - **동작**:
    - `orders` 테이블의 해당 주문에 대해 `payment_status` = `'failed'`, `error_message` = `message` 기록.
    - 관리자 텔레그램으로 결제 실패 알림 발송 (에러 코드, 실패 사유, 주문번호).
  - **클라이언트 연동**: `/payments/fail` 페이지 진입 시 해당 엔드포인트를 자동 호출하여 실패 이력 누락 방지.

- `POST /api/payments/cancel`
  - **설명**: 결제 승인 완료 건에 대한 취소 및 환불을 처리합니다. (관리자 A/S 또는 AI 생성 30초 초과 타임아웃 장애 복구 시 자동 가동)
  - **요청 Body**: `{ orderId, paymentKey, cancelReason }`
  - **보안/인가**: 관리자(`role: admin`) 권한 검증 또는 서버 내부 시스템 호출 검증.
  - **동작**:
    - 토스페이먼츠 취소 API(`https://api.tosspayments.com/v1/payments/{paymentKey}/cancel`) 호출.
    - 성공 시 `orders.payment_status` = `'canceled'`로 갱신하고, 관리자 텔레그램 취소 알림 발송.

- `POST /api/payments/webhook`
  - **설명**: 토스페이먼츠로부터 결제 상태 변경(가상계좌 입금 완료, 승인 취소 등) 비동기 알림을 수신하여 서버 상태를 동기화합니다.
  - **보안 검증**: 토스페이먼츠 웹훅 시크릿 헤더/서명 검증을 거쳐 비인가 페이로드 차단.
  - **멱등 처리**: 이벤트 고유 ID 기반으로 동일 웹훅 중복 수신 시 1회만 트랜잭션 반영.

- `POST /actions/dream-result (toggleDreamPublicAction)`
  - **설명**: 생성된 개별 꿈 결과의 피드 공개 여부를 전환하는 Next.js Server Action
  - **보안 처리**: 비회원의 경우 JWT 토큰(`auth.getUser()`)이 없으므로, HttpOnly 쿠키의 `dream_teller_guest_token` 값을 추출한 뒤 Service Role 클라이언트를 활용해 DB 내부의 소유권을 매칭 및 대조하여 타인의 결과물을 변조할 수 없도록 강제 격리 검증을 수반함.

### 6.4 피드 (Feeds)

### 6.5 AI 처리 및 운영자 알림 파이프라인 (AI Processing & Operator Notifications)

- `POST /api/ai/generate`
  - **설명**: 결제가 완료된 주문의 상품(Product) 정보를 확인하여, 순수 텍스트 해몽인지 이미지 생성이 함께 포함된 해몽 상품인지 판별하고 AI 파이프라인을 분기 처리합니다.
  - **1단계: 결제 상태 및 권한 검증**:
    - 전달받은 `orderId`로 `orders` 테이블을 조회하여 `payment_status === 'paid'` 상태인지 엄격히 검증합니다. 미결제(`pending`, `failed`) 건의 비정상 호출 시 400/403 에러를 반환하여 불필요한 LLM API 비용 발생을 원천 차단합니다.
  - **2단계: 텍스트 생성 (Gemini API)**:
    - 결제가 확인된 모든 꿈 텍스트와 유저가 선택한 4대 학파(`expert_field`: 칼 융, 프로이트, 신경과학, 게슈탈트) 정보를 바탕으로 AI 모델(Gemini)에 해몽 프롬프트를 전송하여 장문의 심층 해석 결과를 JSON/구조화 텍스트로 생성합니다.
  - **3단계: 이미지 생성 (Image Generation API - 옵션 선택 시)**:
    - 결제된 내역이 '해몽 텍스트 + AI 이미지 생성'(2,000원 상품)인 경우에 한하여 호출됩니다.
    - AI 해몽 요약본 및 꿈 원문을 기반으로 시각화용 영문 프롬프트를 생성한 뒤, 이미지 생성 API 모델을 호출하여 이미지를 얻습니다.
    - 생성된 이미지는 Supabase Storage(`dream-images` 버킷)에 업로드하고 Public URL을 발급받아 보존합니다.
  - **4단계: DB 원자적 적재 (`dream_results`)**:
    - AI 해몽 결과(`analysis_text`), 생성 이미지 URL(`image_url`), 상태(`analysis_status = 'completed'`), 갱신시각(`updated_at`)을 `dream_results` 테이블에 반영합니다.
    - 생성 과정에서 타임아웃(30초 초과) 또는 LLM 에러 발생 시 `analysis_status = 'failed'`로 마킹합니다.
  - **5단계: 운영자 텔레그램 실시간 모니터링 알림 발송 (SUCCESS / FAIL)**:
    - 비즈니스 연속성 및 운영 가시성을 위해 결과가 DB에 최종 저장되는 즉시 서비스 운영자 텔레그램 알림 봇으로 실시간 결과(SUCCESS 또는 FAIL)를 통보합니다.

#### 6.5.1 운영자 텔레그램 알림 시스템 규격 (Telegram Bot Notification Specification)

운영자가 서비스 상황(결제 발생, 결제 실패, AI 해석 완료/실패)을 24시간 실시간 모니터링할 수 있도록 Telegram Bot API 기반 알림 시스템을 운영합니다. 모든 알림 발송 로직은 **Non-blocking(`try/catch` 격리)**으로 처리되어, 텔레그램 통신 장애가 사용자 결제나 AI 생성 트랜잭션에 영향을 주지 않아야 합니다.

1. **[알림 1] 결제 완료 및 AI 해몽 요청 트리거 시점 알림 (`REQUEST / TRIGGERED`)**
   - **발송 시점**: 토스페이먼츠 결제 승인 완료(`POST /api/payments/confirm`) 직후 및 AI 분석 파이프라인 가동 시작 시
   - **발송 대상**: 서비스 운영자 텔레그램 방/개인 챗 (`TELEGRAM_CHAT_ID`)
   - **알림 항목**:
     - 알림 타이틀: `[꿈 해몽 분석 요청 접수 🚀]`
     - 결제 상품: 기본 텍스트 해몽(1,500원) / 텍스트 + AI 일러스트 생성(2,000원)
     - 유저 식별자: 회원 ID (`users.id` / 이메일) 또는 비회원 식별 번호 (`phone_number`)
     - 결제 가격: `total_amount` (예: 1,500원, 2,000원)
     - 주문 번호: `order_number`
     - 선택 학파: `expert_field` (칼 융, 지그문트 프로이트, 현대 뇌인지과학, 게슈탈트)
     - 꿈 내용 일부: 개행 제거 후 앞 80~100자 발췌 + `...` 말줄임표 미리보기
     - 요청 일시: 한국 표준시(KST) 포맷

2. **[알림 2] 결제 실패 발생 시점 경보 (`PAYMENT_FAILED`)**
   - **발송 시점**: 결제 진행 중 카드 한도 초과, 잔액 부족, 사용자 취소 등으로 `/api/payments/fail` 호출 시
   - **알림 항목**:
     - 알림 타이틀: `[결제 실패 경보 ⚠️]`
     - 주문 번호: `order_number`
     - 결제 시도 금액: `total_amount` 원
     - 유저 식별자: `user_id` / 연락처
     - 실패 코드: 토스페이먼츠 반환 `code` (예: `REJECT_CARD_COMPANY`, `PAY_PROCESS_CANCELED`)
     - 실패 메시지: 토스페이먼츠 반환 `message`
     - 실패 일시: 한국 표준시(KST)

3. **[알림 3] AI 해몽 완료 및 DB 적재 성공 시점 알림 (`SUCCESS`)**
   - **발송 시점**: Gemini AI 텍스트 생성 및 (선택 시) 이미지 Supabase Storage 업로드 완료 후 `dream_results.analysis_status = 'completed'` DB 커밋 직후
   - **알림 항목**:
     - 알림 타이틀: `[AI 해몽 생성 완료 SUCCESS ✅]`
     - 상태(Status): `SUCCESS`
     - 주문 번호: `order_number`
     - 유저 식별자: `user_id`
     - 처리 소요 시간: 총 생성 시간 (예: `6.8초`)
     - 생성 텍스트 요약: 해몽 텍스트 총 글자 수 및 4대 학파 핵심 결론 1줄 요약
     - 이미지 생성 여부: 이미지 생성 포함 여부 및 Supabase Storage Public URL 링크
     - 완료 일시: 한국 표준시(KST)

4. **[알림 4] AI 해몽 처리 중 오류 발생 시점 알림 (`FAIL`)**
   - **발송 시점**: Gemini API 타임아웃, 이미지 생성 API 에러, 스토리지 업로드 실패, DB 갱신 오류 등으로 `dream_results.analysis_status = 'failed'` 전환 시
   - **알림 항목**:
     - 알림 타이틀: `[AI 해몽 생성 실패 FAIL 🚨]`
     - 상태(Status): `FAIL`
     - 주문 번호: `order_number`
     - 유저 식별자: `user_id`
     - 실패 단계: `TEXT_GENERATION_FAILED` / `IMAGE_GENERATION_FAILED` / `STORAGE_UPLOAD_FAILED` / `DB_PERSISTENCE_FAILED`
     - 상세 에러 내용: Error Message 및 원인
     - 실패 일시: 한국 표준시(KST)
     - 후속 조치 가이드: 관리자 콘솔(`/admin/orders/{id}`) 재시도 링크 제공

5. **환경 변수 및 보안 규격**:
   - `TELEGRAM_BOT_TOKEN`: Telegram `@BotFather`를 통해 발급받은 비공개 HTTP API 토큰 (`.env.local` 및 프로덕션 환경변수 등록 필수)
   - `TELEGRAM_CHAT_ID`: 알림을 수신할 운영자 개인 계정 또는 운영진 그룹 채팅방 고유 ID
   - **보안**: 알림 메시지 내 민감 정보(비회원 비밀번호 해시, 토스 결제키 시크릿 등)는 절대 포함하지 않고, 꿈 원문은 프리뷰(100자 이내)로 마스킹하여 전송함.

## 7. 데이터베이스 스키마 (Database Schema)

Supabase PostgreSQL 환경을 기준으로 구성하되, 인증 테이블(`auth.users`)과 연결되는 어플리케이션 전용 Public 테이블을 정의합니다. MECE 원칙에 따라 명확히 역할을 분리했습니다.

### 7.1 Users (`users`)

회원(소셜)과 비회원의 정보를 통합 관리하는 테이블입니다.

- **`id`** (UUID, Primary Key, **Not Null**): 고유 식별자 (Supabase `auth.users`의 PK와 1:1 매핑)
- **`role`** (String, **Not Null**): 사용자 역할 (`member`, `guest`, `admin`)
- **`provider`** (String, **Not Null**): 가입 경로 (`google`, `kakao`, `guest`)
- **`email`** (String, Null): 회원 이메일 (소셜 로그인 회원용)
- **`nickname`** (String, Null): 사용자 닉네임
- **`phone_number`** (String, Null): 비회원 식별 및 주문 조회용 전화번호
- **`guest_password_hash`** (String, Null): 비회원용 암호화된 비밀번호
- **`created_at`** (Timestamp, **Not Null**): 계정 생성 일시
- **`updated_at`** (Timestamp, **Not Null**): 정보 최종 수정 일시

### 7.2 Orders (`orders`)

사용자의 꿈 분석 요청 및 토스페이먼츠 결제 내역을 매핑하는 테이블입니다.

- **`id`** (UUID, Primary Key, **Not Null**): 내부 시스템의 고유 주문 식별자
- **`order_number`** (String, Unique, **Not Null**): 토스페이먼츠의 `orderId`로 사용될 고유 주문 번호
- **`user_id`** (UUID, Foreign Key, **Not Null**): 결제를 진행한 `users.id` 참조
- **`total_amount`** (Integer, **Not Null**): 총 결제 금액
- **`payment_status`** (String, **Not Null**): 결제 상태 (`pending`, `paid`, `failed`, `refunded`, `canceled`)
- **`payment_key`** (String, Null): 토스페이먼츠 승인 키 (결제 성공 시 저장)
- **`approved_at`** (Timestamp, Null): 토스페이먼츠 결제 승인 시각
- **`error_message`** (Text, Null): 결제 실패/에러 시 사유 메시지
- **`dream_content`** (Text, **Not Null**): 유저가 직접 입력한 원본 꿈 내용
- **`expert_field`** (String, **Not Null**): 선택한 해몽 전문 분야 (`freud`, `jung`, `neuroscience`, `gestalt` 등)
- **`includes_image`** (Boolean, **Not Null**): AI 이미지 생성 옵션 구매 여부
- **`created_at`** (Timestamp, **Not Null**): 주문서 생성 일시
- **`updated_at`** (Timestamp, **Not Null**): 결제 및 상태 업데이트 일시

### 7.3 Dream Results (`dream_results`)

결제 완료 후 생성되는 AI 해몽 결과물과 이미지 URL, 피드 공개 여부를 담당하는 테이블입니다.

- **`id`** (UUID, Primary Key, **Not Null**): 고유 식별자
- **`order_id`** (UUID, Foreign Key / Unique, **Not Null**): 매칭되는 `orders.id` 참조 (1:1 관계)
- **`analysis_status`** (String, **Not Null**): 해몽 진행 상태 (`processing`, `completed`, `failed`)
- **`analysis_text`** (Text, Null): AI(Gemini)가 생성해낸 심층 해몽 텍스트
- **`image_url`** (String, Null): AI(Gemini)가 묘사해준 꿈 이미지 URL (옵션 미구매 시 Null)
- **`is_public`** (Boolean, **Not Null**): Feed 페이지 공유 노출 여부 (`true` or `false`)
- **`created_at`** (Timestamp, **Not Null**): 해몽 작업 최초 생성 일시
- **`updated_at`** (Timestamp, **Not Null**): 해몽 결과 또는 노출 여부 수정(Update) 통제용 일시

### 8.2 백엔드 E2E 테스트 목록 (Backend & API E2E Tests)

Next.js Route Handlers(API Routes), Server Actions, 토스페이먼츠 결제 승인, Gemini AI 심층 해몽 생성 파이프라인, 비회원 데이터 격리 및 관리자 권한 통제의 무결성을 보장하기 위한 종단간(E2E) 백엔드 테스트 시나리오 목록입니다.

> **💡 백엔드 도메인/기능 단위 묶음 (Test Suites)**
> 1. **인증 및 세션 (`BE-E2E-001` ~ `BE-E2E-004`)**: 미지원 OAuth 방어, 콜백 라우팅, 비회원 게스트 세션 발급, 세션/쿠키 무효화
> 2. **회원 프로필 (`BE-E2E-005` ~ `BE-E2E-006`)**: 미인증 프로필 차단, 닉네임 유효성/XSS 방어
> 3. **주문 및 비회원 격리 (`BE-E2E-007` ~ `BE-E2E-010`)**: 단가 위변조 차단, 게스트 비밀번호 단방향 해시, IDOR 소유권 검증, 비회원 데이터 격리
> 4. **토스 결제 파이프라인 (`BE-E2E-011` ~ `BE-E2E-016`)**: 승인 금액 검증, 중복 승인 멱등성, 알림/트리거, 결제 실패 기록, 취소/환불, 웹훅 서명 검증
> 5. **AI 심층 해몽 엔진 (`BE-E2E-017` ~ `BE-E2E-020`)**: 미결제 호출 원천 차단, 4대학파 리포트 생성, 이미지 생성/Storage 업로드, API 타임아웃 회복
> 6. **피드 및 공유 통제 (`BE-E2E-021` ~ `BE-E2E-022`)**: 비공개 꿈 격리, 피드 공개 토글 권한 검증
> 7. **관리자 운영 및 A/S (`BE-E2E-023` ~ `BE-E2E-025`)**: 통계 지표 RBAC, 1:1 조인 주문 목록, 관리자 AI 해몽 수동 재발행
